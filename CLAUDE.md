## Dev environment
- `npm install --legacy-peer-deps` — peer dep conflicts otherwise (AsyncStorage / RN combo).
- `npx expo start --ios` — boots iOS simulator with Expo Go. Needs Xcode; on a real iPhone, App Store Expo Go only runs the newest SDK, so use TestFlight.
- `npm run verify` — types, lint, unit and routing tests. `npm run e2e` drives every flow headlessly against `expo start --web --port 8099` and opens no windows. **Don't start that server with `CI=1`**: CI mode turns off Metro's file watching, so edits silently don't reach the browser.
- If a runtime `HostFunction: TypeError` appears (Fabric strict prop check), check for version drift and run `npx expo install --fix` with legacy-peer-deps enabled.
- **`ReferenceError: Property 'x' doesn't exist` while `tsc` is clean** means Metro is serving a stale incremental bundle — it happens after adding exports to a widely-imported module like `src/lib/points.ts`. Restart with `npx expo start --clear`. Don't go hunting in the source; it's the bundler.

## Gotchas worth remembering
- `PressableScale` puts `className`/`style` on the node that also carries the animated transform. Keep it that way — an inner wrapper swallows layout props and silently collapses `flex-1` button rows.
- Score by **local** day. `Completion.completedAt` is an ISO UTC stamp, so slicing its date prefix files evening sessions under tomorrow. `totalsByDay` goes through `dayKey(new Date(...))` for this reason.
- `totalsByDay` **recomputes** points from `(cat, minutes)` and ignores the stored `Completion.points`. Keep it that way — if the formula changes and history keeps old values, the pacer gets set by differently-priced days and becomes unreachable. The stored field is kept only so the recap can show the number banked at the time.
- Nothing in the UI loops. See the doctrine at the top of `src/lib/motion.ts` before adding any animation.
- **The visual system:** text sizes come from the scale in `tailwind.config.js` (`text-caption` 12 … `text-title1` 28), not `text-[13.5px]`. Rows of a list share one `Group` with `Divider`s (`src/components/ui/Group.tsx`); a card is for something that stands alone or needs its own decision. Labels are sentence case, never tracked capitals. One filled accent button per screen; secondary actions are tinted or plain text. Phrases are written out rather than joined with " · ".
- **The store owns ending a session; the Focus screen only displays it.** One timer in `AppStore` aimed at `endsAt`, plus a check on resume. Don't tick it from a screen, or a session stops ending when that screen isn't mounted, and don't add a per-second tick to the store, or the whole app re-renders.
- **Only a Done tap finishes a task.** A timer reaching zero banks the minutes, keeps the task and asks on the recap. Deleting an unfinished task because 25 minutes passed is the worst failure this app can have.
- **A session has four endings, and each is a `finishFocus` mode or `abandonFocus`.** Done finishes the task. The clock running out (`expired`) keeps it and asks. Stop for now (`stopped`) keeps the minutes and the task, and the recap offers Don't count this session as the way back. Under a minute in, Stop just cancels. Don't put a confirm in front of any of them: the take-back comes after.
- **The race lane is `RaceTrack`, shared by Home's card and the recap.** It holds its move while `live` is false, because Home stays mounted under Focus and the recap and a move made there is never seen. The recap passes the points from before the session, then the points after, and `scalePoints` so the beads don't slide while the runner travels.
- **Restoring an export only ever adds** (`src/lib/backup.ts`). It never overwrites or removes, so it's safe to do twice. Keep it that way.
- **The Live Activity and the widget are Swift, in `targets/widgets`,** turned into an Xcode target by `@bacons/apple-targets` at prebuild. `modules/focus-activity` is the native module that drives them, and `src/lib/liveActivity.ts` is the only thing that calls it, from the store. `FocusAttributes.swift` exists twice, word for word, because the app and the extension are separate Swift modules and ActivityKit pairs them by that type's name and shape. A test fails if the copies differ.
- **`bash scripts/widget-preview.sh` draws the widget and the Live Activity on this Mac,** every state, light and dark, as PNGs in `widget-preview-out/`. It's the design loop for the extension: seconds, against twenty minutes for a simulator run. It works because the views (`FocusViews`, `NextTaskViews`, `RaceLane`, `Runner`) are plain SwiftUI that take plain values, with the WidgetKit and ActivityKit parts kept to three thin files it leaves out, and colours behind `Palette` so a stand-in can replace the asset catalog. Keep new views that way. Add a state to `scripts/widget-preview/Scenes.swift` when a view gains one. What it can't show is the system's own drawing: the timer-driven bar and the Dynamic Island's shape.
- **A timer's `Text` takes all the width it's offered** and shoves its neighbours. `TimerDigits` sizes the space with hidden ordinary digits and lays the live ones over them. Use it for any countdown in the extension.
- **The extension's Swift doesn't compile on this Mac** (the installed SDK is macOS 13, with no ActivityKit). `swiftc -parse targets/widgets/*.swift` catches syntax in the three files the preview skips. `npx expo prebuild -p ios --no-install` followed by `cd ios && LANG=en_US.UTF-8 pod install` does run here and proves the target and the pod are wired up. The real build is `gh workflow run ios-simulator.yml -f groups='["lock-screen"]'`.
- **`.gitignore` anchors `/ios/` to the root.** Unanchored, it also ignored `modules/focus-activity/ios`, and the module's Swift stayed out of the repository while every local check passed.
- **The welcome ends inside a session.** `.maestro/01-first-run.yaml` finishes that session with Done so Home is empty again, which `02-capture-sort` relies on.
- **Leave a flow with `router.dismissTo('/')`, not `replace('/')`.** Replace leaves a duplicate Home underneath that a back swipe reveals. `src/__tests__/navigation.test.tsx` shows both.
- **React to change only after `hydrated`.** Loading saved data looks like a change against the pre-load zeros. That's how every cold start used to fire level-up confetti, and how a deep link used to close itself.
- `RCTAsyncStorageExcludeFromBackup: false` in `app.json` is load-bearing. AsyncStorage excludes itself from iCloud backups by default, so without it every phone upgrade loses all of a user's data.
- Web resolves Reanimated from source (`metro.config.js`) so `className` on `Animated.View` works there like it does on native. Without that branch, button rows collapse and card fills vanish, but only in a browser.
- `PressableScale`'s accessibility lives on the outer node, because the touch overlay has no children to build a label from. Don't move it back.
- **No `KeyboardAvoidingView` inside a sheet** (`presentation: 'modal'`). It measures its own frame from the sheet's top and the keyboard from the screen's, so it lifts short by the sheet's offset and a bottom button ends up under the suggestion bar. Use `useKeyboardPadding()` from `src/lib/keyboard.ts`, which measures from the bottom, or a ScrollView with `automaticallyAdjustKeyboardInsets`.
- **Text scales up to 3.6× at iOS's largest size**, which the web build never shows. Screen titles and header subtitles stop at `TITLE_SCALE` (2×). At the accessibility sizes `useLargeText()` is true, and side-by-side layouts stack there (the Home header, the companion card, a task row's Focus button). A fixed-height screen needs a ScrollView that centres its content when it fits, like the Focus screen's. Check new screens in the simulator's `large-text` group.
- Limb angles in `Sprite` are clockwise from hanging down, so a right-hand arm reaches outward at a *negative* angle. Positive swings it behind the head, where it can't be seen.
- Import fonts per weight (`@expo-google-fonts/.../400Regular`). The package index bundles all 18 weights of each family.
- `expo prebuild` rewrites the `ios` and `android` scripts in `package.json`. If you run it to inspect the native config, restore them and delete `ios/`.
- **Colors live in `src/lib/colors.json`**, read by both Tailwind and `theme.ts`. In a component, `const palette = useColors()`. Class names like `text-ink` follow the theme by themselves through a plugin in `tailwind.config.js`. On anything filled with accent, use `text-on-accent` or `palette.onAccent`, never white: in dark, accent is a light color and white on it is unreadable.
- **The appearance setting overrides the window** (`src/lib/appearance.ts`), so light stays the default even on a phone set to dark. Default stays light on purpose. Colors are measured, not assumed: add a screen or state to the contrast scenarios in `scripts/e2e.mjs`.
- The contrast audit looks through empty clear layers (`elementsFromPoint`) because every `PressableScale` label sits under its own touch overlay. When it stopped at the topmost element it skipped every button in the app, and white labels on the dark theme's light accent went unmeasured.
- **There's no Xcode on this Mac, but real iOS is available:** `gh workflow run ios-simulator.yml` compiles the Release app on GitHub's macOS runners (Xcode 26.0.1, free on a public repo) and drives it on iOS 26 simulators with `.maestro/` flows, at the largest text size, on an iPhone SE, and with a dark phone. `-f groups='["flows"]'` drives only some devices, and `-f reuse_build=<run id>` skips the compile. `gh run download` gets each flow's screenshots and log, and `results.txt` says why a flow failed.
- Writing `.maestro/` flows: Maestro's driver taps Allow on system prompts by itself, so never tap it yourself; a second tap lands on the app. Change tabs through `common/tab.yaml`, which retries until the tab is selected. Wait for outcomes (`extendedWaitUntil`), not animations: the companion breathes forever, so `waitForAnimationToEnd` never settles on You or Insights, and taps can go missing on CI's software-rendered simulators.
- Store materials live in `store/`, including what still needs a real device (`store/RELEASE.md`). `docs/` is published to GitHub Pages, so keep anything private out of it.
